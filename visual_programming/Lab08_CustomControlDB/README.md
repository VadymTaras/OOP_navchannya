## 📌 Огляд архітектури проєкту

Проєкт є сучасною інженерною панеллю телеметрії апаратних показників (Hardware Telemetry Dashboard), що демонструє всі ключові аспекти створення власних візуальних компонентів та інтеграції з базою даних на платформі **.NET 8.0 Windows Forms**:

1. **Користувацький компонент `SensorCardControl` (UserControl):**
   - Успадкований від `System.Windows.Forms.UserControl`.
   - Містить власні властивості з атрибутами дизайнера: `[Category]`, `[Description]`, `[DefaultValue]`, `[DefaultProperty]`, `[DefaultEvent]`.
   - Властивості конфігурації: `SensorName`, `Value`, `Unit`, `MinValue`, `MaxValue`, `MinThreshold`, `MaxThreshold`, `Status`, `CardAccentColor`.
   - Власна подія `AlertTriggered` (використовує клас `AlertEventArgs`), яка генерується при виході значень за встановлені критичні пороги.
   - Метод `UpdateTelemetry(double newValue)` забезпечує автоматичний перерахунок статусу (`Normal`, `Warning`, `Critical`), оновлення прогрес-бару та зміну колірного оформлення (бейдж, акцентна лінія, фон).

2. **Сервіс бази даних `DatabaseService` (Repository Pattern):**
   - Забезпечує персистентне зберігання історії вимірювань телеметрії у JSON-сховищі `Data/telemetry_vault.json`.
   - Потокобезпечні операції додавання записів (`InsertRecord`), вибірки з фільтрацією (`GetFilteredRecords`), розрахунку аналітичної статистики (`GetStatistics`), очищення бази (`ClearHistory`) та експорту в CSV (`ExportToCsv`).

3. **Головне вікно моніторингу `MainForm`:**
   - Динамічне розміщення екземплярів `SensorCardControl` для 4 сенсорів: Температура CPU, Використання RAM, Трафік мережі, Тиск охолодження.
   - Моделювання надходження телеметрії через `System.Windows.Forms.Timer` з підтримкою випадкового коливання (Random Walk), покрокового оновлення та штучної генерації аварійного сплеску.
   - Відображення історії вимірювань у `DataGridView` з кольоровою диференціацією статусів (зелений, жовтий, червоний).
   - Багаторівнева фільтрація (за типом сенсора, за статусом, тільки аварійні) та експорт у CSV.
   - Окремий термінал подій `txtAlertLog` з фіксацією спрацювання події `AlertTriggered`.

## 🛠 Відмінності між типами компонентів у Windows Forms

| Тип компонента | Базовий клас | Спосіб створення | Сфера застосування |
| :--- | :--- | :--- | :--- |
| **UserControl (Складений компонент)** | `UserControl` | Об'єднання готових стандартних елементів (Label, ProgressBar, Panel) у візуальному дизайнері | Готові функціональні блоки інтерфейсу: картки датчиків, форми введення адреси, медіаплеєри |
| **Inherited Control (Успадкований елемент)** | Стандартний контрол (`Button`, `TextBox`, `TextBox` тощо) | Успадкування та перевизначення подій / методів (`OnPaint`, `OnKeyDown`) | Розширення існуючого контролу: TextBox з валідацією IP-адреси, Button з анімацією |
| **Custom Control (Повністю власний контрол)** | `Control` | Повне малювання через GDI+ у методі `OnPaint()`, ручна обробка миші й клавіатури | Специфічні елементи без аналогів: кругові стрілочні прилади, аудіо-еквалайзери, граф-візуалізатори |
