# Система управління плагінами з ізольованими контекстами (js-closures-part1-variant-10)

Проєкт реалізує архітектурну модель розширення функціоналу додатка за допомогою зовнішніх модулів (плагінів). Вся логіка побудована на базі принципів функціонального програмування, використання замикань (Closures) для інкапсуляції даних та проектування за паттерном Модуль (Module Pattern).
## Структура проєкту

```markdown
js-closures-part1-variant-10
 ├── src
 │    ├── plugin-core.js          # Ядро менеджера (Module Pattern на замиканнях)
 │    ├── plugins.js              # Опис ізольованих плагінів (Dependency Injection)
 │    └── app.js                  # Обробник інтерфейсу користувача та подій
 ├── assets
 │    └── style.css               # Адаптивні стилі лог-панелі та карток
 ├── index.html                   # Головна сторінка з慢панеллю управління
 └── README.md                    # Суцільний файл документації

```

## Технічний опис архітектурних рішень та паттернів

### 1. Інкапсуляція даних та Приватні змінні (Closures)

Функція `createPluginManager()` створює область видимості (лексичний контекст), яка виступає приватним сховищем для внутрішніх об'єктів системи: масиву `plugins`, посилань на слухачі подій `eventListeners` та внутрішнього стану додатка `sharedState`. Ці структури є абсолютно недоступними із глобальної області видимості та захищені від прямої некоректної мутації ззовні.

### 2. Паттерн Модуль (Module Pattern)

Менеджер повертає лише чітко визначений публічний об'єкт із методами `register`, `execute` та `unregister`. Це класична реалізація патерну Модуль через фабричні замикання. Внутрішній метод `createPluginAPI` динамічно генерує об'єкт сервісів (Shared API), який передається плагіну, створюючи додатковий ізольований рівень замикання під кожен окремий модуль.

### 3. Впровадження залежностей (Dependency Injection)

Плагіни є повністю незалежними об'єктами. Під час виклику хука життєвого циклу `install(api)`, менеджер самостійно інжектує (впроваджує) згенерований ізольований інтерфейс API всередину плагіна. Плагін зберігає посилання на це API у своєму внутрішньому замиканні й використовує його для логування або взаємодії із системою.

### 4. Усунення витоків пам'яті (Memory Leak Prevention)

Поширена проблема систем розширення — накопичення застарілих посилань на події в глобальному об'єкті `window` після деінсталяції модулів. Для усунення цього ризику в ядрі створено приватний реєстр `eventListeners`. При реєстрації плагіна через `api.onEvent()`, посилання на колбеки автоматично кешуються. Під час виконання хука `uninstall` (метод `unregister`), менеджер каскадно викликає `removeEventListener` для кожного збереженого посилання, повністю звільняючи пам'ять пристрою.

## Інструкція із запуску програми

1. Склонуйте цей репозиторій на локальну машину за допомогою Git.
2. Відкрийте кореневу папку проєкту `js-closures-part1-variant-10` у середовищі розробки **CLion** (або іншій IDE від JetBrains).
3. Скористайтеся вбудованим локальним вебсервером: відкрийте файл `index.html` у редакторі коду, переведіть курсор у верхній правий кут вікна редактора та оберіть іконку вашого браузера (наприклад, Chrome).
4. Програма автоматично розгорнеться за адресою локального хоста 
`http://localhost:63342/js-closures-part1-variant-10/`.
