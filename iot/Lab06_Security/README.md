# Практична робота 6. Безпека в IoT: загрози безпеки, методи криптографічного захисту даних та пристроїв

Цей репозиторій містить програмний комплекс криптографічного захисту для систем Інтернету речей (IoT), розроблений у межах дисципліни **«Технології IoT та SMART-технології»** (викладач Клименко О.А.).

## 1. Архітектура комплексу безпеки

Архітектура побудована за парадигмою **Zero Trust Architecture (ZTA)** з багатошаровою верифікацією пакетів на стороні брокера/шлюзу:

```
[ Сенсорний вузол ESP32 ]
         │
         ▼
  1. Генерація показників телеметрії (T, H, P, Battery)
  2. Шифрування Payload: AES-256-GCM (Конфіденційність)
  3. Формування Header: Nonce (UUIDv4) + Timestamp (UTC) + Auth Token
  4. Підпис всього пакету: HMAC-SHA256 (Цілісність та автентичність)
         │
         │  (Небезпечний бездротовий канал передачі: Wi-Fi / Zigbee / LoRaWAN)
         ▼
[ Шлюз безпеки IoT Security Gateway ]
  Крок 1. Перевірка Device ID та Auth Token (Автентифікація пристрою)
  Крок 2. Константно-часова перевірка HMAC-SHA256 (Захист від підміни / MitM)
  Крок 3. Валідація Timestamp window & Nonce cache (Захист від Replay-атак)
  Крок 4. Автентифіковане дешифрування AES-256-GCM (Конфіденційність та GCM Tag)
  Крок 5. Реєстрація події в Security Audit Log та збереження телеметрії
```

## 2. Структура проєкту

- `crypto_utils.py` — криптографічне ядро системи:
  - Симетричне шифрування та дешифрування AES-256-GCM з 12-байтним nonce (IV) та 16-байтним тегом автентифікації.
  - Обчислення та перевірка HMAC-SHA256 підпису з константно-часовим порівнянням (`compare_digest`).
  - Клас `ReplayAttackValidator` для контролю актуальності часової мітки та унікальності nonce.
  - Канонічна серіалізація JSON для детермінованого розрахунку хешів.
- `secure_iot_node.py` — модель захищеного сенсорного вузла на базі MCU (ESP32/STM32):
  - Збір сенсорних даних.
  - Упаковка телеметрії у криптографічний пакет.
  - Підтримка ін'єкцій аномалій для перевірки реакції системи безпеки.
- `security_gateway.py` — захищений шлюз обробки телеметрії:
  - Білий список пристроїв і секретних ключів.
  - Багаторівневий конвеєр фільтрації пакетів.
  - Структурований журнал інцидентів безпеки (`Security Audit Log`).
- `attack_simulation.py` — комплексний симулятор атак з виводом детальної звітності:
  - Базовий тест легітимної передачі даних.
  - Атака Man-in-the-Middle (підміна даних/шифротексту в транзиті).
  - Атака Replay Attack (повторна передача перехопленого пакету та застаріла мітка часу).
  - Атака Unauthorized Access (незареєстрований пристрій або недійсний токен).
  - Фальсифікація цифрового підпису HMAC.
- `requirements.txt` — зовнішні залежності (`cryptography`).

## 3. Модель загроз (OWASP Top 10 for IoT)

Розроблена система протидіє таким ключовим загрозам:
1. **OWASP IoT 01: Слабкі паролі / відсутність автентифікації** — використання унікальних 256-бітних ключів та токенів автентифікації для кожного окремого сенсора.
2. **OWASP IoT 02: Небезпечні мережеві сервіси** — шлюз приймає пакети виключно після суворої багатоетапної валідації.
3. **OWASP IoT 03: Небезпечні інтерфейси екосистеми** — сувора канонізація вхідного JSON та захист від ін'єкцій.
4. **OWASP IoT 07: Небезпечна передача даних** — наскрізне шифрування AES-256-GCM захищає від перехоплення конфіденційної інформації (eavesdropping).
5. **OWASP IoT 08: Відсутність керування пристроями / аудиту** — централізований Security Audit Log з фіксацією типу події, мітки часу та стану.

## 4. Інструкція запуску

1. Встановіть необхідні залежності:
   ```bash
   pip install -r requirements.txt
   ```
2. Запустіть повнофункціональний симулятор атак:
   ```bash
   python attack_simulation.py
   ```
