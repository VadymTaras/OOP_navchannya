Детальний опис структур даних та архітектури системи
Проєкт реалізує асинхронну подієво-орієнтовану систему керування сповіщеннями (Notification Queue System) на базі клієнтського стека технологій (HTML5/CSS3/ES6+). Архітектура системи побудована на принципі розподілу обов'язків (Separation of Powers) між об'єктом представлення даних (Notification) та центральним менеджерським хабом керування потоками (NotificationManager).

1. Компонентна структура об'єкта Notification
   Клас Notification є інкапсульованою сутністю, яка безпосередньо відповідає за життєвий цикл (Lifecycle) одного візуального елемента сповіщення від моменту його рендерингу до повної деструктуризації.

Властивості стану: Кожен екземпляр класу оперує ізольованим контекстом пам'яті, що містить метадані (id, title, message, type), конфігурацію поведінки (duration, persistent, playSound) та змінні внутрішнього таймінгу (remainingTime, startTime, timerId).

Інкапсуляція DOM-дерева: Об'єкт самостійно генерує власну HTML-розмітку, імпортує стилі кастомних тем та інтегрує обробники подій (click, mouseenter, mouseleave) безпосередньо на створений вузол.

Маніпуляція часом (Pause/Resume): Механізм призупинення автовидалення при наведенні курсора (hover) реалізовано за допомогою математичного розрахунку дельти часу. При події mouseenter таймер setTimeout анулюється, а залишок часу обчислюється за формулою:
remainingTime = remainingTime - (Date.now() - startTime).
При події mouseleave створюється новий відліковий процес із оновленим залишком часу.

Низькорівневий аудіо-синтез: Для виконання вимоги звукових сповіщень не використовуються сторонні аудіо-файли. Впроваджено роботу з веб-інтерфейсом AudioContext API. Система динамічно генерує звукову хвилю заданої частоти (нота Ре, 587.33 Гц) через вбудований осцилятор (OscillatorNode), що забезпечує миттєву та енергоефективну звукову віддачу.

2. Архітектура та менеджмент черги в NotificationManager
   Клас NotificationManager виступає в ролі архітектурного контролера та координатора, який оркеструє потоки сповіщень на рівні всього вебдодатка.

Structure даних "Черга" (Queue): Черга неактивних сповіщень реалізована на базі стандартного динамічного масиву JavaScript за принципом FIFO (First In, First Out) — першим прийшов, першим пішов. Коли кількість активних елементів на екрані сягає ліміту maxNotifications, нові запити на створення проходять операцію буферизації через метод queue.push().

Структура даних "Стек" (Stacking): Візуальне розташування елементів регулюється властивістю stacking. Контролер підтримує два режими додавання нових вузлів до активного масиву activeNotifications та DOM-дерева контейнера:

Режим top: нові сповіщення вставляються на початок через insertBefore(), зміщуючи старі вниз.

Режим bottom: нові сповіщення додаються в кінець через appendChild().

Динамічне керування контейнерами: Контролер використовує ліниву ініціалізацію (Lazy Initialization) контейнерів позиціонування. Спеціальні DOM-блоки для шістьох базових позицій (top-left, top-right тощо) не створюються заздалегідь, а динамічно генеруються та кешуються в об'єкті this.containers лише у разі реального виклику сповіщення у цю зону.

Асинхронний зворотний зв'язок (Callback Loop): Зв'язок між менеджером та об'єктом сповіщення реалізовано через патерн "Слухач". Під час створення об'єкта Notification, менеджер передає йому свій приватний колбек onClose. Коли сповіщення завершує свій цикл існування (по таймеру або кліку), воно самостійно викликає цей колбек, передаючи свій id. Менеджер видаляє його з масиву активних, перевіряє буфер черги через queue.shift() і, за наявності елементів, миттєво рендерить наступне сповіщення.
